# GENQUANTAA ADLC — MongoDB Data Models and Schemas

## 1. Overview
The GENQUANTAA ADLC platform utilizes MongoDB for flexible, high-fidelity lifecycle records, audit trails, and evidence tracking. When running offline or without an active MongoDB daemon, a resilient embedded store guarantees zero disruption.

---

## 2. Core Collections

### `organizations`
Tenant organization boundaries.
- `id`: string (UUID or slug)
- `name`: string
- `created_at`: ISO timestamp

### `adlc_projects`
Authoritative project definitions and stage state machine.
- `id`: `prj_<hex>`
- `name`: string
- `description`: string
- `intended_use`: string
- `domain`: string
- `risk_tier`: "Low" | "Medium" | "High" | "Critical"
- `owner`: string
- `organization_id`: string
- `status`: "active" | "on_hold" | "completed" | "archived"
- `current_stage`: LifecycleStage enum (e.g. `discovery_intake`)
- `stages`: Map of stage IDs to stage execution metadata:
  - `stage`: string
  - `status`: "draft" | "pending" | "running" | "awaiting_review" | "approved" | "completed" | "failed"
  - `started_at`: ISO timestamp
  - `completed_at`: ISO timestamp
  - `reviewer`: string
  - `approval_status`: string
  - `prerequisites_met`: boolean
  - `errors`: array of strings
  - `warnings`: array of strings
- `is_demo`: boolean
- `created_at`: ISO timestamp
- `updated_at`: ISO timestamp

### `project_documents`
Ingested project input artifacts.
- `id`: `doc_<hex>`
- `project_id`: string
- `filename`: string
- `file_type`: "pdf" | "docx" | "txt" | "csv"
- `file_size_bytes`: integer
- `sha256_checksum`: string
- `storage_path`: string
- `extracted_text`: string
- `created_at`: ISO timestamp

### `project_requirements`
Structured requirement specifications generated by Agent 1.
- `id`: `req_<hex>`
- `project_id`: string
- `title`: string
- `description`: string
- `type`: "functional" | "regulatory" | "safety" | "performance"
- `priority`: "low" | "medium" | "high" | "critical"
- `acceptance_criteria`: array of strings
- `source_reference`: string (document name and section citation)
- `review_status`: "draft" | "approved" | "rejected"
- `reviewer`: string
- `reviewed_at`: ISO timestamp
- `created_at`: ISO timestamp

### `project_tasks`
Work breakdown items produced by Agent 2.
- `id`: `tsk_<hex>`
- `project_id`: string
- `title`: string
- `description`: string
- `suggested_role`: string
- `priority`: string
- `status`: "draft" | "pending" | "in_progress" | "completed" | "blocked"
- `linked_requirements`: array of requirement IDs
- `dependencies`: array of task IDs
- `created_at`: ISO timestamp

### `evaluation_runs`
Deterministic test execution records produced by Agent 7.
- `id`: `test_run_<hex>`
- `project_id`: string
- `test_suite_version`: string
- `total_tests`: integer
- `passed_tests`: integer
- `failed_tests`: integer
- `status`: "passed" | "failed"
- `duration_seconds`: float
- `results`: array of test assertions (test_id, requirement_id, status, duration, stdout/stderr)
- `executed_at`: ISO timestamp

### `risk_assessments`
Risk analysis items produced by Agent 8.
- `id`: `risk_<hex>`
- `project_id`: string
- `hazard_description`: string
- `severity`: "low" | "medium" | "high" | "critical"
- `likelihood`: "low" | "medium" | "high"
- `proposed_controls`: array of strings
- `required_evidence`: array of strings
- `acceptance_status`: "draft" | "accepted" | "requires_mitigation"
- `created_at`: ISO timestamp

### `traceability_links`
Bidirectional links connecting requirements, tasks, tests, results, and evidence.
- `id`: `link_<hex>`
- `project_id`: string
- `source_type`: "requirement" | "task" | "test_case"
- `source_id`: string
- `target_type`: "task" | "test_case" | "test_result" | "evidence"
- `target_id`: string
- `created_at`: ISO timestamp

### `evidence_records`
Immutable verification evidence records.
- `id`: `evid_<hex>`
- `project_id`: string
- `title`: string
- `category`: "test_log" | "document_hash" | "approval_audit" | "risk_report"
- `sha256`: string
- `payload`: object
- `timestamp`: ISO timestamp
